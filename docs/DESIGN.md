# Leadman — game mode design & gate map

> Status: **shipped as a RuneLite plugin.** The gate engine, menu enforcement, GE
> filtering, sidebar, per-item editor, and profile persistence described here are
> implemented in `src/main/java/com/leadman`. The bundled ruleset (~4 000 item rules)
> is generated by `tools/generate-rules.mjs` and verified against the OSRS Wiki item
> mapping. This document is the *design reference*; [`README.md`](../README.md) is the
> player-facing summary.

---

## 0. The mode in one paragraph

Leadman is a self-imposed challenge mode played on a **normal (non-Ironman) account**,
enforced client-side by a RuneLite plugin. You play under Ironman conduct — no player
trades, no picking up other players' drops — with a **Grand Exchange** that starts fully
locked and opens item-by-item. An item becomes tradeable when you can *legitimately
produce it yourself* at your current skill levels, or when you **obtain** one and it has
no fabrication recipe (boss drops, uniques, supplies).

Lead is softer than bronze. The mode is *easier* than Bronzeman on acquisition and
*harder* on consumption.

---

## 1. Action gates (not just two booleans)

The engine tracks permissions **per action**, not as a single “use” blob. Each can be
locked independently (including via custom overrides):

| Action | Blocks |
| --- | --- |
| **Trade** | GE buy, sell, offers |
| **Shop** | NPC shop buy |
| **Eat / Drink** | Food and potions |
| **Wear / Wield** | Armour, weapons, jewellery |
| **Use** | Tool actions (e.g. chop with an axe) |
| **Activate** | Teleports, rubbing charges |
| **Bury** | Bones and ashes (custom rules only by default) |
| **Cast** | Spells when a consumed rune is locked (optional rune gate) |

Trade and use diverge on purpose. Raw swordfish at 50 Fishing unlocks GE/shop for the
**raw** item; cooked swordfish is a different item gated at 45 **Cooking** for both trade
and eat. Looting a saradomin brew may unlock trade (obtain) but never drink until 81
Herblore.

### 1.1 Trade and shop

```
tradeUnlocked(item) =
  fabricable(item)                    -- meets any SKILL path at current levels
  OR everObtained(item)               -- for GE items with no skill path
  OR customRule.trade satisfied

shopUnlocked(item) = same fabrication/obtain logic, with optional shop-specific overrides
```

- **fabricable** — real (non-boosted) levels satisfy at least one `UnlockPath`.
- **everObtained** — persisted; first time the account genuinely held the item.
- Shop purchases do **not** set `everObtained` (anti-launder).
- All ~4 000 GE tradeables have a catalog entry (`FREE` if no recipe). Items with no skill
  path still need **one obtain** before trade/shop/use open.

### 1.2 Use actions

```
useUnlocked(item) =
  fabricable(item)
  OR (no skill path AND (not GE tradeable OR everObtained))
  OR customRule.use satisfied
  -- subject to per-skill USE toggles (§2.1)
```

**everObtained never bypasses fabrication** for items that have a skill recipe. Looting a
brew does not let you drink it.

Where OSRS already enforces a level (Attack for scimitars, Defence for plate, Ranged for
ammo), Leadman does not duplicate it unless the player opts in (§2).

### 1.3 Multiple paths (OR)

An item can have several `UnlockPath`s. You satisfy the item when **any one path** is
fully met; a path is met when **all** its requirements in that path are met.

```
fabricable(item) = OR over paths ( AND over reqs in path )
```

Amulet of glory: one path, two reqs — `Crafting 80 AND Magic 68` for trade. Steel bolts
may have Smithing and Fletching paths; the lower path wins automatically.

> **Backlog (§12):** `allowAlternativeSkilling` — optional OR between *primary* fabrication
> and *alternate* obtain routes (Thieving stalls, Sailing wrecks). Engine already supports
> multi-path OR; data mapping is the work.

## 2. The unifying rule

> **Trade/shop follow the fabrication ladder (or obtain for unmapped GE items). Use is
> gated only where the game provides no requirement of its own.**

| Class | Vanilla requirement | USE gated by default |
| --- | --- | --- |
| Food | none | **yes** — swordfish, 45 Cooking to eat |
| Potions | none | **yes** — brew, Herblore to drink |
| Jewellery, worn | none | **yes** — glory, 80 Crafting to wear |
| Charges / teleports | none | **yes** — glory, 68 Magic to rub |
| Permanent equipment | Attack / Defence / Ranged | no — scimitar at 40 Attack |
| Tools (axes) | Woodcutting on the axe rule | WC level to **chop**, not Smithing |
| Ammunition | Ranged | no — opt-in Fletching gate |
| Runes | spell Magic level | no — opt-in RC gate at cast time |

**Axes:** smithing gates **trade**; woodcutting level on the item rule gates **chop**.
Pickaxes are not in the smithing generator — they fall through obtain/catalog rules.

**Smithing gates equipment** (off by default): when on, wearing also needs the smithing
level; when off, only vanilla Attack/Defence apply (platebody at 40 Def, trade at 99
Smithing).

**Smithing gates tools** was removed — it only affected axes, deadlocked gathering, and
did not cover pickaxes.

### 2.1 Configurable use-gate toggles

| Toggle | Default | Gates |
| --- | --- | --- |
| Cooking gates food | **on** | eat |
| Herblore gates potions | **on** | drink |
| Crafting gates wearing jewellery | **on** | wear |
| Magic gates charges and teleports | **on** | activate |
| Fletching gates ammunition | off | use (ammo) |
| Runecrafting gates runes | off | cast (via rune check) |
| Smithing gates equipment | off | wear (adds smithing on top of vanilla) |

Jewellery splits Crafting (wear) and Magic (teleport) independently.

Ironman conduct toggles: block others' drops, block player trade, **disable GE** (hard
block all GE ops).

## 3. Item classification

1. **Fabricable / gatherable** — skill paths in `leadman-rules.json`. Trade/shop need
   fabrication; use follows §2.
2. **Drop / reward** — no recipe; GE items unlock on first **obtain** (whip, supplies).
3. **FREE (catalog)** — every remaining GE name has a stub rule for the editor and
   obtain gate; no skill path until overridden.
4. **Custom** — per-item overrides in config JSON; any action, any levels.

### 3.1 Depth, boosts, variants

- **Final step only** — no input-chain (Herblore 38 for brew, not Farming 32 for ranarr).
- **Base levels only** — boosts do not count.
- **Name normalisation** — charges, ornaments, doses collapse to one rule (`ItemNames`).

## 4. Unlock sources & persistence

| Source | Trade/shop | Use | Popup / chat |
| --- | --- | --- | --- |
| Skill level-up → fabricable | yes | per toggle | yes, batched |
| First obtain (no skill path) | yes | yes | yes |
| Shop purchase | no | no | no |
| Custom rule | per field | per field | on block |

Profile: `~/.runelite/leadman/<accountHash>.json` — `obtained`, `recentUnlocked` (last 20),
`seen`, `activities`. Fabrication is recomputed every login from live levels.

## 5. Skill-by-skill gate map

*(Illustrative levels; shipping data is generated.)*

Cooking, Fishing, Smithing, Crafting, Magic, Fletching, Herblore, Runecrafting, etc. —
see generator ladders in `tools/generate-rules.mjs` and [`docs/LADDERS.md`](LADDERS.md).

Notable implemented ladders beyond core metal/food/jewellery:

- Rune packs (shop) aligned with rune RC levels
- Armour sets at platebody smithing tier
- Cannonballs (smithing trade; sailing USE for mithril+)
- Crossbows (fletching), bolt tips (smithing/fletching), teleport tablets
- Black armour sets → FREE (not smithable)

Thieving / Sailing alternate obtain routes → **backlog** (§12).

## 6. Known edge cases

### 6.1 Runes and teleports — resolved

Runes TRADE-gated by default; USE/cast gated only if **Runecrafting gates runes** is on.
Gate applies at **cast** (rune consumption), not only holding runes — stops elemental
staffs supplying locked runes.

### 6.2 Ammunition — resolved

Same pattern; Fletching gate is opt-in.

### 6.3 Quest deadlocks — open

Quest-required items may need an allowlist bypass. `ACTIVITY` paths exist in the model;
curated list not shipped.

### 6.4 Early game — open

Starter unlock seed at profile creation not implemented.

## 7. Configuration (implemented)

| Key | Default |
| --- | --- |
| `gateFood` / `gatePotions` / `gateJewel` / `gateCharged` | on |
| `gateAmmo` / `gateRunes` / `gateEquipment` | off |
| `blockOtherPlayerDrops` / `blockPlayerTrade` | on |
| `allowedTradePartners` | `""` (comma-separated display names) |
| `allowTradeWithParty` | off (RuneLite Party plugin, same party) |
| `disableGe` | off |
| `showPopup` / `popupChat` / `explainBlocks` | on |
| `popupBatchThreshold` | 5 |
| `popupDuration` | 4000 ms |
| `customRules` | `[]` (hidden JSON) |

Not implemented: `mode` preset enum, `questItemBypass`, `starterKit`, `staffLaundering` as
separate keys (some behaviour covered by toggles above).

## 8. Data model & generation

Rules keyed by **normalised name**, not item id. Bundled files:

- `leadman-rules.json` — generated (~4 000+ items)
- `overrides.json` — hand-maintained corrections
- `ge-tradeables.json` / `ge-item-ids.json` — GE universe for obtain detection

Pipeline: `node tools/generate-rules.mjs [--verify]`, `node tools/fetch-ge-tradeables.mjs`.

Every GE tradeable gets at least a `FREE` stub so the catalog and editor can target it.

---

## 9. Enforcement limits

Client-side only (honour system). Enforced via menu removal, GE search filter, chat
explanations. Cannot cancel existing GE offers or block non-menu actions.

---

## 10. UI (implemented)

- **Sidebar** — 20 most recent unlocks (view-only), search, ⚙ opens catalog
- **Catalog dialog** — full list, bright/gray status, click to edit, reset all custom rules
- **Per-item editor** — trade, shop, eat, drink, wield, use, teleport, bury; override flag
- **Unlock popup** — batched on big level-ups; coloured chat lines
- **Inventory overlay** — dim items with any locked action; examine lists restrictions

---

## 11. Settled decisions

1. Trade vs use split; obtain does not grant use on fabricable items.
2. Runes/ammo TRADE-gated; USE/cast opt-in.
3. Vanilla combat levels respected for equipment unless Smithing-gates-equipment is on.
4. No Smithing-gates-tools toggle.
5. GE catalog completeness + obtain gate for items without recipes.
6. Custom per-action overrides are first-class.
