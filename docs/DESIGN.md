# Leadman — game mode design & gate map

> Status: **implemented.** The engine, gates, enforcement and UI described here exist in
> `src/main/java/com/leadman`. The level tables in §5 are illustrative prose; the shipping
> data is generated by `tools/generate-rules.mjs` (see §8) and every generated item name
> is verified against the live OSRS Wiki item mapping. The purpose of this document is to
> fix the *rule system*, not the data.
>
> Three of the four questions in §11 are settled. The remaining one — the quest-item
> allowlist — is wired up but has an empty list behind it.

---

## 0. The mode in one paragraph

Leadman is a self-imposed challenge mode played on a **normal (non-Ironman) account**,
enforced client-side by a RuneLite plugin. You play under Ironman conduct — no player
trades, no picking up other players' drops, no shared loot — with one exception: the
**Grand Exchange**, which starts fully locked and opens up item-by-item. An item becomes
GE-tradeable when you can *legitimately produce it yourself*, i.e. when you hit the
skill level that fabricates it. Items with no fabrication path (boss drops, quest
rewards) unlock the Bronzeman way: by obtaining one.

Lead is softer than bronze. The mode is *easier* than Bronzeman on acquisition and
*harder* on consumption.

---

## 1. There are two gates, and they are independent

Everything in this design reduces to two booleans per item.

| Gate | Question | Blocks |
|---|---|---|
| **TRADE** | May this item pass through the Grand Exchange? | GE buy, GE sell, offer creation |
| **USE** | May I equip / eat / drink / cast / apply this item? | `Wear`, `Wield`, `Eat`, `Drink`, `Cast`, charge ops |

They are computed separately and can disagree in both directions:

- Raw swordfish at 40 Fishing → **USE** allowed (it is not usable anyway), **TRADE** locked.
- Saradomin brew looted from a boss at 40 Herblore → **TRADE** unlocked (you obtained it),
  **USE** locked (you cannot brew it).

### 1.1 TRADE rule (universal, applies to every item)

```
tradeUnlocked(item) = fabricable(item) OR everObtained(item) OR hasNoGate(item)
```

- `fabricable` — you currently meet the requirements of at least one skilling recipe
  that produces the item.
- `everObtained` — you have held the item at least once (Bronzeman-style, persisted).
- `hasNoGate` — the item has no mapped skilling path and no custom rule (see §4.5).

Buying from an NPC shop does **not** set `everObtained`. The raw-swordfish example is
explicit about this: shop-bought does not launder an item into the GE.

### 1.2 USE rule

```
useUnlocked(item) = fabricable(item) OR hasNoSkillPath(item)
```

Note what is *absent*: `everObtained` is not in this formula. Looting an item never
grants the right to use it. That is the potion example.

`hasNoSkillPath` is why an Abyssal whip is freely wieldable at 70 Attack — nothing
fabricates a whip, so there is nothing to gate on.

## 2. The unifying rule (and the inconsistency in the spec)

The six examples in the brief do not all follow the same rule as written. Two conflict:

- **Rune scimitar** — 90 Smithing to trade, but *equip normally at 40 Attack*.
- **Amulet of glory** — 80 Crafting + 68 Magic to trade **and to equip**.

Both are permanent equipment obtained as drops. Under a naive "gate everything" reading,
the scimitar would need 90 Smithing to wield. Under a naive "gate nothing" reading, the
glory would be free to wear.

The rule that reproduces **all six** examples, and the later clarification on runes and
ammunition, with no exceptions list:

> **TRADE is gated on every item. USE is gated only where the game provides no
> requirement of its own.**

The reasoning: a rune scimitar already asks for 40 Attack, and that requirement *is* the
permission — you earned the right to wield it, so a looted one is fair to use. Nothing at
all stands between you and eating a shark, drinking a brew, or putting on an amulet of
glory. For those, Leadman supplies the requirement the game left out.

| Class | Vanilla requirement | USE gated by default |
|---|---|---|
| Food | none | **yes** — Cooked swordfish, 45 Cooking to eat |
| Potions / drinks | none | **yes** — looted potion, Herblore level to drink |
| Jewellery, worn | none | **yes** — Glory, 80 Crafting to put on |
| Charges and teleports | none | **yes** — Glory, 68 Magic to rub |
| Permanent equipment | Attack / Defence / Ranged | no — Rune scimitar, 40 Attack |
| Tools | the gathering skill | no — Rune axe, 41 Woodcutting |
| Ammunition | Ranged | no — Rune arrows, 40 Ranged |
| Runes | the spell's Magic level | no — the spellbook already gates the cast |

Ammunition and runes were USE-gated in the first draft of this document. They are not,
because the game gates them already: rune arrows need 40 Ranged, and every spell carries
a Magic level. Adding a Fletching or Runecrafting gate on top is a *second* restriction on
an item that already has one, which is the thing the scimitar example rules out.

Every one of these is a per-skill toggle (§2.1), so a player who wants "you can only fire
arrows you could fletch" turns Fletching's use gate on, independently of Runecrafting.

**Consequence worth stating out loud:** a rune axe is trade-locked until 86 Smithing but
usable the moment you have 41 Woodcutting. If the "no USE gate on tools" carve-out did not
exist, the mode would deadlock — you would need 85 Mining and 86 Smithing before you could
swing the axe that feeds Firemaking and Fletching. (Pickaxes are not smithable in OSRS at
all, so they fall through to shop and drop unlocks either way.)

### 2.1 Configurable strictness

Three presets, and under Standard a toggle per skill:

| Preset | USE gate covers |
|---|---|
| **Bronzeman+** | nothing — TRADE gates only |
| **Standard** (default) | whatever the per-skill toggles say |
| **Strict** | everything, including equipment and tools; ignores the toggles |

| Toggle | Gates | Default |
|---|---|---|
| Cooking gates food | food | **on** |
| Herblore gates potions | potions | **on** |
| Crafting gates wearing jewellery | putting a glory on | **on** |
| Magic gates charges and teleports | rubbing it, firing the teleport | **on** |
| Fletching gates ammunition | arrows, bolts, darts, javelins, chins | off |
| Runecrafting gates runes | every rune a cast consumes | off |
| Smithing gates equipment | weapons, armour, shields | off |
| Smithing gates tools | axes, harpoons, knives | off |

The ones defaulting to *on* are exactly those with no vanilla requirement. The rest are
opt-in, one skill at a time, so tightening Fletching does not drag Runecrafting along with
it.

**Jewellery splits in two**, because two skills made it and they gate two different acts.
Crafting shaped the amulet; Magic put the teleports in it. So an amulet of glory carries
`Crafting 80` for wearing and `Magic 68` scoped to activation. Trading one still needs
both — you must be able to make the whole thing — but the two use gates move
independently: turn the Crafting gate off and a glory you may now wear still will not
teleport you until 68 Magic.

## 3. Item classification

Every tradeable item lands in exactly one bucket. The bucket determines which unlock
sources apply.

1. **Fabricable** — at least one skilling recipe produces it.
   → gated by that recipe's requirements on both gates.
2. **Gatherable** — produced by a gathering skill directly (raw fish, logs, ores, herbs,
   uncut gems, chinchompas). Mechanically identical to (1); listed separately because the
   requirement is a *gathering* level, and because these are almost never USE-gated.
3. **Drop-only** — no recipe (whip, Bandos, Barrows, most dragon items, boss uniques).
   → TRADE unlocks on first obtain. USE ungated.
4. **Reward-only** — quest, diary, minigame-shop and activity rewards (Ava's device,
   fighter torso, void, Mage Arena gear, Graceful).
   → TRADE unlocks on completing the source activity, or on first obtain. USE ungated by
   default, but these are the prime candidates for the custom list (§4.5).
5. **Unmapped / free** — bones, ashes, coins, jugs, buckets, feathers, most raw
   materials with no level attached.
   → both gates open by default; fully addressable from the custom list.

### 3.1 Multiple recipes

An item can have several paths. You satisfy the item when you satisfy **any one path**;
you satisfy a path when you meet **all** requirements in it.

```
fabricable(item) = OR over paths ( AND over reqs ( playerLevel(skill) >= level ) )
```

Amulet of glory has one path with two requirements: `Crafting 80 AND Magic 68`.
Steel bolts have paths via Smithing and via Fletching; the lower effective path wins
automatically.

### 3.2 Depth: final recipe only

The gate checks **only the final production step**, never the input chain. Prayer potions
need ranarr (32 Farming to grow) but the gate is Herblore 38 alone. Rationale: shops and
already-unlocked GE items supply inputs, so chain-checking would double-count and make
the mode unplayable without adding meaning.

### 3.3 Boosts do not count

Gates read **base levels**, not boosted. A Crafting potion does not unlock dragonstone
jewellery. Levels are re-evaluated on `StatChanged` against the real level.

### 3.4 Variants

Charges, degradation, ornament kits, imbues, trouver-protected and noted forms all
collapse to a canonical item before lookup — `ItemVariationMapping` plus a hand-kept
override table. Amulet of glory (6)/(5)/…/(t) is one rule. Ahrim's robetop 0/25/50/75/100
is one rule.

## 4. Unlock sources & events

| Source | Sets TRADE | Sets USE | Fires popup |
|---|---|---|---|
| Skill level-up satisfying a recipe | yes | yes | yes — batched |
| First obtaining a drop-only item | yes | — | yes |
| Quest / diary / activity completion | yes | — | yes |
| NPC shop purchase | no | no | no |
| Custom rule satisfied | per rule | per rule | yes |

### 4.1 Level-up unlocks are bulk events

One Fletching level can unlock dozens of items. The unlock queue must batch: a single
popup reading **"55 Fletching — 14 items unlocked"** with the full list in the sidebar
and chat, rather than 14 sequential popups. Cap the popup queue and collapse overflow.

### 4.2 Retroactive scan

On login, recompute `fabricable` for all items against current levels and quest state.
Anything newly true is unlocked silently (no popup storm) if this is the first scan for
the profile, and with popups otherwise.

### 4.3 Persistence

Per-account-hash file, Bronzeman-style: `~/.runelite/leadman/<accountHash>.json`
holding `everObtained` ids, completed-activity flags, custom rules, and a
`seenUnlocks` set for popup de-duplication. `fabricable` is never persisted — it is
derived from live levels every login.

### 4.4 Ironman conduct enforcement

Because the account is a normal account, the plugin — not the server — has to enforce
everything an Ironman gets for free:

- Block `Take` on ground items where `TileItem#getOwnership() != OWNERSHIP_SELF`.
  This is a real RuneLite API and is the clean way to implement the "no other players'
  drops" rule.
- Block the `Trade with` menu option on players, and the trade-request interface.
- Block duel stakes, shared clan/group storage, and loot-sharing interfaces.
- Warn on entering PvP-loot situations.

All of this is **advisory** — see §9 for what the client genuinely cannot prevent.

### 4.5 The custom rule list

The configurable list for items with no natural skill link. Each entry:

```json
{ "item": "Big bones", "gates": ["USE", "TRADE"], "reqs": [{ "skill": "PRAYER", "level": 30 }] }
```

Ships with an off-by-default **Prayer progression** preset (bones and ashes laddered to
Prayer level), plus empty slots for Agility (Graceful), Slayer (minigame gear) and
anything else the player wants to tighten. Editable in the sidebar with item search, a
skill dropdown and a level spinner; exportable/importable as JSON so rulesets can be
shared.

## 6. Where this breaks, and the exceptions we need

Six places where a naive reading makes the mode unplayable rather than hard. The first
two are **resolved** by the rule in §2; the rest still need handling.

### 6.1 Teleports die at Runecrafting 54 — resolved

Law runes are 54 RC and nature runes are 44 RC. USE-gating runes would have meant:

- **No teleports of any kind until 54 Runecrafting.** Varrock teleport is a 25 Magic
  spell you could not cast until three-quarters of the way up an unrelated skill.
- **No High Alchemy until 44 RC**, removing the main early money-maker.
- Ancient Magicks (death 65, blood 77) and Arceuus spells (soul 90) locked out of the
  entire mid-game.
- Charged jewellery is gated, so glory and dueling-ring teleports would not have filled
  the gap either. Both routes closing at once.

**Resolution:** runes are TRADE-gated only by default. The spellbook already gates every
cast behind a Magic level, so a rune you obtained and can legally cast with is fair to
use. Players who want the harder version turn on *Runecrafting gates runes*.

The gate, when enabled, is applied at the **cast** rather than at the rune item. A fire
staff supplies fire runes you never owned, so gating the item alone would let a 30k staff
launder a third of the rule. `staffLaundering` exists to turn that off for anyone who
disagrees.

### 6.2 Ammunition capped by Fletching — resolved

Rune arrows at 75 Fletching and dragon darts at 95 would have meant Ranged never outruns
Fletching, with blowpipe plus dragon darts pushed past most players' end state.

**Resolution:** same as 6.1. Arrows carry their own Ranged requirements — 40 for rune, 30
for adamant — so the game is already gating them. Ammunition is TRADE-gated by default,
with *Fletching gates ammunition* available for anyone who wants both.

### 6.3 Quest deadlocks

Some quests hand you an item and require you to consume or wear it. If the gate blocks
that, quest progress hard-stops, which can cascade (a blocked quest blocks a skill unlock
which blocks an item). Needs a **quest-item allowlist**: items bypass all gates while
they are required by an incomplete quest. This list has to be curated by hand.

### 6.4 The early game

Levels 1–20 have almost nothing unlocked and no shop money. Tutorial and starter gear,
plus a small always-unlocked set (bronze/iron equipment, shrimp, air/mind/water runes),
should be seeded at profile creation.

### 6.5 Late Herblore is the real difficulty curve

Saradomin brews 81, super combats 90, divine potions 97, anti-venom+ 94. High-level PvM
is effectively gated behind ~90 Herblore. This one is probably *correct* and is the
mode's identity — but it should be a stated design choice, not something discovered at
85 Herblore.

### 6.6 Sharks at 80 Cooking

Best-in-slot healing is locked until 80 Cooking; monkfish (62) carries the entire
mid-game. Also correct and thematic, but worth confirming.

## 8. Data model & generation

```java
enum Gate { TRADE, USE }

record Requirement(Skill skill, int level) {}

record UnlockPath(
    PathType type,          // SKILL, QUEST, DIARY, ACTIVITY, SHOP
    List<Requirement> reqs,
    String sourceRef        // "Smithing:rune scimitar", "Quest:Dragon Slayer I"
) {}

record ItemRule(
    int canonicalId,
    ItemClass itemClass,    // FABRICABLE, GATHERABLE, DROP_ONLY, REWARD_ONLY, FREE
    ConsumeClass consume,   // FOOD, POTION, AMMO, RUNE, CHARGED, EQUIPMENT, TOOL, NONE
    List<UnlockPath> paths
) {}
```

`consume` drives which gates apply; `paths` drives whether they are open.

**Generation pipeline** — hand-writing ~4000 rules is not viable and would rot.

1. Pull the tradeable-item universe and canonical ids from the OSRS Wiki prices API item
   mapping.
2. Pull recipes from the OSRS Wiki Cargo tables (`production_json` / recipe data) and the
   skill-calculator modules — these already encode "item X requires skill S level L".
3. Emit `leadman-rules.json` as a bundled plugin resource.
4. Layer a hand-maintained `overrides.json` on top for: consume-class assignment, the
   quest-item allowlist, variant collapsing, and every exception in §6.
5. Ship a validation pass that fails the build on unmapped tradeable items, so new game
   content surfaces as a task instead of a silent free unlock.

The generator lives in the repo and is re-runnable per game update. Overrides are never
regenerated.

## 9. What the plugin can and cannot enforce

RuneLite plugins cannot change server behaviour. Every restriction here is client-side
and defeatable by disabling the plugin — the same honour system Bronzeman runs on.
Within that:

**Genuinely enforceable** (the action goes through a menu op the client controls):

- Removing `Eat` / `Drink` / `Wear` / `Wield` / `Take` / `Trade with` entries via
  `MenuEntryAdded`.
- Blocking spell casts by filtering spell-widget menu entries.
- Hiding GE search results for locked items (`GrandExchangeSearched` → override the
  result set) — this is exactly Bronzeman's mechanism.
- Blocking GE offer creation on a locked item id.

**Advisory only:**

- Anything triggered without a menu click.
- Existing offers placed before the plugin was enabled.
- Items already in the inventory when a rule tightens.

Design implication: when an action is blocked, say *why* — "Locked: needs 45 Cooking to
cook a swordfish" — because the player is opting into this, and a silently dead menu
entry reads as a bug.

- **Sidebar panel** — searchable unlocked/locked browser; every locked item shows its

- **Inventory / bank overlay** — optional dim or padlock icon on locked items.
- **Chat feedback** — one line on every blocked action, with the requirement.

## 11. Decisions

1. **The unifying rule** (§2) — *settled.* USE is gated only where the game provides no
   requirement of its own. Everything else is TRADE-gated only.
2. **Runecrafting / teleports** (§6.1) — *settled.* Trade-gated by default; the harder
   version is a per-skill toggle. No grace bands and no utility exemption: both were
   fudges softening a gate that should not have been on by default.
3. **Ammunition** (§6.2) — *settled*, same way.
4. **Quest-item bypass** (§6.3) — still open. `questItemBypass` is on by default but the
   allowlist behind it is empty, so nothing bypasses anything yet. Needs a curated list of
   quest-required items before it does anything useful.

### Still to build

- Cannonball tiers above steel, teleport tablets, crossbows and bolt tips (`overrides.json`).
- A preset library for the custom rule list — the Prayer ladder for bones and ashes,
  Agility for Graceful.
